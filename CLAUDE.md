# Salle de jeux — instructions pour Claude

Site qui regroupe des mini-jeux (solo, party, en ligne, défis du jour, IA).
En ligne : https://roidescrabesboubou.github.io/le-projet/ (GitHub Pages, mise à jour 1 à 2 min après un push).

## Règles du projet
- Réponds en français.
- Chaque mise à jour est commitée et poussée sur `main` (pas de branche, pas de PR).
- HTML, CSS et JavaScript « vanilla » : pas de framework, pas de npm, pas d'étape de build.
- Un jeu = un dossier `jeux/<slug>/`, avec parfois un fichier de données à côté (`mots.js`, `questions.js`…).
- Git : `C:\Program Files\Git\cmd\git.exe` (Git pour Windows, identifiants GitHub enregistrés).
- Quand `firebase-regles.json` change, publie-le toi-même après le push : `firebase.cmd deploy --only database` (projet `salle-de-jeux-249d2`, déjà connecté, commande autorisée dans `.claude/settings.local.json`), puis dis-moi que c'est publié. Sous PowerShell, toujours `firebase.cmd` / `npm.cmd` (scripts .ps1 bloqués).

## Ajouter un jeu
1. Copier `jeux/_modele/` vers `jeux/<slug>/`.
2. Ajouter l'entrée dans `jeux/commun/catalogue.js` (même slug), le slug dans la bonne catégorie de `SALLE_CATEGORIES` (fin de `catalogue.js`), et ses mots-clés dans `MOTS_CLES` (`index.html`).
3. S'il a un classement : ajouter le slug dans `firebase-regles.json` (puis le publier avec `firebase.cmd deploy --only database`).
4. Tester, commit, push sur `main`.

L'état choisi dans le panel admin passe avant celui de `catalogue.js`.

Accueil : 6 catégories choisies avec moi (`SALLE_CATEGORIES` à la fin de `catalogue.js`, adresse `#jeux/<catégorie>`), chacune avec la liste de ses jeux par défaut : Défis du jour, Soirée entre amis, Duels et plateau, Casino, Histoires avec l'IA, Arcade et solo, plus Apéro (cachée tant que ses jeux le sont). L'onglet 🗂️ Catégories du panel admin crée, renomme, réordonne, masque ou supprime des catégories (`reglages/categories/<id>` = {titre, emoji, desc, c1, c2, o, suppr}) et change les catégories d'un jeu (`reglages/cats/<slug>` = "jour soiree", "" = aucune) ; ces choix passent avant le code. `SALLE_CATS(regl)` (catalogue.js) donne la liste finale, utilisée par l'accueil et l'admin. **Nouveau jeu : l'ajouter dans la bonne liste** (sinon il tombe dans Arcade et solo). Un jeu peut être dans plusieurs listes. Pas de page « tous les jeux ». Les jeux `ia: true` sont cachés de l'accueil sauf pour les comptes avec accès IA. Barre de recherche : nom, description, étiquettes et mots-clés de `MOTS_CLES` (`index.html`, ex. « tetris » → blocs) : **ajoute des mots-clés pour chaque nouveau jeu**. En groupe 👥 d'au moins 2 membres, seuls les jeux étiquetés `Multijoueur` s'affichent (seul dans son groupe, on voit tout) : mets cette étiquette à tout jeu qui a une salle en ligne. Message de bienvenue à la 1re visite (`salle_bienvenue_vue`). Boîte à idées en bas de l'accueil : `idees/<id>` = {t, n, u, d, s} (une par minute et par identité via `idees_dernier/<uid>`, lisible seulement par les admins), rangées dans l'onglet 💡 Idées de l'admin (nouvelle / à garder / faite / écartée).

## Choix techniques
- **Firebase** (projet `salle-de-jeux`) : comptes, classements (top semaine remis à zéro le lundi 0 h, heure de Paris, et tous les temps), séries, médailles, groupes, jetons, état des jeux réglé dans l'admin.
- **Joueurs sans compte** : identité Firebase anonyme (`Compte.anonyme()`, fournisseur « Anonyme » activé dans Authentication). Séries, résultats du jour, scores, Éveil, Shikaku, Coup de Feu sont rangés sous cet uid (`Classement.ecrireMoi`) : personne ne peut modifier l'entrée d'un autre. `scores/<jeu>/<uid>` = record de tous les temps, `scores_semaine/<jeu>/<uid>` = record de la semaine (champ `w`).
- **IA** : appels directs depuis le navigateur, la clé reste dans le navigateur. Gemini en principal, Claude Haiku 5.5 en secours automatique. Modèle Gemini conseillé : gemini-3.1-flash-lite (le moins cher des fiables, clé passée en payant). Relais (ia.js et Quintuplées) : Gemini essaie d'abord ses autres modèles (gemini-3.5-flash-lite puis gemini-3.6-flash, même clé, sans attente) quand le modèle choisi est surchargé, réflexion « minimal » sur 3.1/3.5/3.6, « low » sinon ; une autre IA principale est réessayée 3 fois en cas de surcharge passagère (503, « high demand », réponse coupée) avant de passer à la suivante ; le relais ne vaut que pour un message, le suivant repart de l'IA choisie. Réponse JSON coupée ou illisible = rejetée et redemandée. OpenRouter : `google/gemma-4-26b-a4b-it:free` (rapide), secours Gemma 4 31B (plus de `openrouter/free`, trop lent), sans réflexion (`reasoning.effort: "none"`), `provider.sort: "throughput"`, `max_tokens` borné. Groq : `openai/gpt-oss-120b` (llama-3.3 arrêté le 16/08/2026), palier gratuit 8 000 tokens/min, sauté quand la partie est trop longue. Les jeux `ia: true` sont réservés aux comptes autorisés (sauf invités venus par un lien de salle).
- **En ligne** : pas de serveur à moi. Salles avec code/lien via un relais public ; c'est l'hôte qui fait tourner la partie.
  Relais essayés dans l'ordre HiveMQ, Mosquitto, puis EMQX (`ORDRE` dans reseau.js) : EMQX jette un message sur deux au-delà d'environ 13 par seconde (~190 ms), injouable en temps réel ; un code qui finit par 1 = EMQX. Pastille « 🌐 relais · ping » en bas à gauche pendant une salle (`salle.ping`). Un invité absent plus de 25 s (téléphone en veille) est retiré par l'hôte ; à son réveil il ne se voit plus dans `_liste` et renvoie `_bonjour` avec le même id → `surArrivee` (les jeux qui gardent les joueurs, comme La Soirée et Le Contrat, le remettent en jeu avec ses points).
  **Serveur Cloudflare** (`serveur/`, Workers + Durable Objects, plan gratuit) pour les jeux en temps réel : une salle = un Durable Object qui fait tourner la partie (`serveur/src/jeux/<slug>.js`, physique partagée avec le navigateur, ex. `jeux/sumo/sim.js`). Codes en « 9 » final. Côté jeu : `Reseau.creer(jeu, {serveur: true})` essaie le serveur puis le relais ; `salle.serveur`, `salle.chef()`. Adresse dans `SERVEUR` (reseau.js) ; essai en local : `localStorage.salle_serveur = "ws://localhost:8787"` + config « serveur » de launch.json (`wrangler dev`). Déployer : `npx.cmd wrangler deploy` dans `serveur/` (exception à « pas de npm », seulement pour ce dossier). Branché : Sumo.
  L'Arène Éclair a une connexion directe WebRTC, coupée (`DIRECT = false`) car elle buguait sur de vrais appareils.
- **Sources externes** : Deezer (extraits 30 s) et AnimeThemes (openings). ccMixter (instrus Creative Commons du Freestyle, copiées dans le dépôt, crédits affichés dans le jeu : obligatoires en CC BY). Spotify écarté (plus d'extraits depuis fin 2024). ZoneSons écarté tant qu'ils n'ont pas donné leur accord.
- **Casino** : 1 000 jetons au premier passage (une fois par jeu : chaque jeu de casino a son propre portefeuille, les jetons ne passent pas d'un jeu à l'autre) ; sous 50 jetons, 500 offerts le lendemain ; aucun autre moyen d'en gagner.
